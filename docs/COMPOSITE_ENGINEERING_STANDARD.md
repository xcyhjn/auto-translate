# 可推广的复合工程标准

## 适用目标

本标准适用于把媒体处理、模型推理、规则处理、人工编辑和发布交付组合为一条长流水线的项目。核心目标不是追求全自动，而是确保每个阶段可复现、可恢复、可审计、可人工接管。

## 五层工程模型

1. **输入事实层**：保存原始媒体、外部元数据和人工确认输入；不得被下游自动覆盖。
2. **机器工件层**：保存 ASR、时间轴、翻译和分析中间文件；每个工件必须有 schema 与输入指纹。
3. **规则与证据层**：人工确认的 glossary 是硬规则；网页或平台信息是 `advisory` 证据；缺失事实标记为 `unknown`。
4. **人工决策层**：人工编辑 ASS、人工接受的术语和反馈样例拥有高于机器建议的权威。
5. **交付层**：QA 报告、最终 ASS、烧录视频和 manifest 形成可追溯发布包。

## 阶段契约

每个可组合阶段应返回稳定信封：

- `schema_version`
- `stage`
- `status`: `pending/running/success/failed/skipped`
- `outputs`
- `warnings`
- `error`
- `metadata`

CLI、UI、worker 和批处理器只消费契约，不复制业务逻辑。新增阶段先定义输入、输出、失败语义和重跑条件，再接入编排。

## Artifact 与缓存规则

- 指纹至少覆盖输入绝对路径、size、mtime_ns、关键配置 hash、提示词/术语 hash 和 schema version。
- 指纹不匹配、schema 不支持、JSON 损坏或输出缺失一律视为 cache miss。
- JSON 使用同目录临时文件、flush/fsync 和原子替换；失败时清理临时文件。
- manifest 只记录定位和验证所需信息，不记录 API key、cookie 或其他秘密。
- 缓存命中不能越过人工 gate，也不能把旧机器基线提升为人工确认事实。

## 证据等级

- `confirmed`：用户或授权审核者明确确认，可进入硬规则或正式交付。
- `advisory`：来自元数据、检索或模型的辅助证据，只能用于建议与复核。
- `unknown`：来源、时间或事实不足；必须保留未知，禁止推断补齐。

Evidence sidecar 必须带 `project_id` 与 `input_fingerprint`。跨项目或跨输入的记录不得自动合并；动态检索只能补充 glossary，不能替代或截断它。

## 人工 Gate

- 人工 ASS 是字幕编辑源文件；重烧录必须保留现有文本，只做确定性的安全变换。
- Bilibili/平台重复检索保持 advisory，不阻断下载、翻译、烧录或反馈学习。
- 反馈进入 prompt 或规则前必须可查看、可拒绝；学习集与评测集不得复用同一条样例。
- 删除文件、改变数据库 schema、添加依赖、改变输入事实来源或自动提交外部系统必须人工批准。

## CLI 与编排

- CLI 只解析参数、调用既有服务并规范退出码。
- 独立阶段必须可 dry-run；dry-run 不读取大媒体、不联网、不写业务产物。
- 不支持的命令 fail-closed，返回非零退出码和清晰说明，不能假装成功。
- UI 使用同一 Python API/阶段契约，不维护第二套流水线。

## 验证金字塔

1. 静态：Python 编译、JavaScript 语法、`git diff --check`。
2. 单元：schema、fingerprint、原子写入、parser、退出码、隔离规则。
3. 集成：旧 CLI、worker、UI API、manifest 和人工 reburn 契约。
4. 真实环境：ffmpeg、下载器、GPU、远程模型和真实媒体。
5. 人工视觉：实际 ASS/视频检查裁切、遮挡、双语间距、换行和窗口尺寸。

只有已执行的层级可以报告为已验证；静态成功不能代替真实媒体或视觉验证。

## 回滚与提交

- 一个提交只包含一个可独立回滚的逻辑切片。
- 在脏工作树中显式暂存文件，禁止 `git add -A`。
- 不提交 `.env`、密钥、cookie、视频、字幕成品、数据库、运行日志或个人反馈数据。
- 变更阶段契约、缓存 schema 或事实来源时，必须提供兼容读取或迁移说明。

## 完成定义

一个优化任务完成时必须同时具备：实现、针对性测试、兼容性说明、风险/开放 gate、可回滚提交，以及能让下一位 agent 不依赖口头上下文继续工作的文档。
